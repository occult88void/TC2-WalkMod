# Проверки 22 ноября 2026

Целевой сценарий выхода из автомобиля в Freedrive пока требует подтверждённого native backend. В этой ветке подготовлен узкий factory probe 18 для получения недостающего кода.

## Выполнено

- Проверен архив от 22 ноября и исходники веток Bootstrap16 и Bootstrap17. Рабочая ветка `development-2026-11-22` создана от `analysis-19-bootstrap17-semantic-capture`.
- В файлах Bootstrap16 поиск little-endian хешей `0F3F48DD`, `51E17990`, `2155AD67`, `430810CA` дал ноль совпадений. Покрытие захвата ограничено сохранёнными окнами.
- Вызов `0x366750` из HQ dispatch проверяет тип существующего объекта, затем при необходимости переходит в `0x366940`. Последняя функция также получает существующую ссылку через `+0x60 -> +0x10`. По показанному коду этот участок не предоставляет фабрику.
- `0x119FCB0` находится внутри инструкции, начинающейся в `0x119FCAE`. Использовать его как адрес функции нельзя. Начало проверенного getter — `0x119FC60`, прямой callee — `0x119EBE0`, байтов callee в Bootstrap16 нет.
- Путь `0xECCEE0 -> 0x366750 -> 0xB97F90` передаёт существующую ссылку в selector `0x30`. В `0xB97FC0` вызывается `0x4301E0`, затем идут дополнительные обновления. Реализации `0x4301E0` в доступных окнах не найдено. Семантика назначения local player здесь остаётся UNKNOWN.

## Что собирает probe 18

По одному нажатию Ctrl+Shift+F10 в Freedrive код ищет ровно четыре хеша в доступных исполняемых секциях. Для первых 16 совпадений каждого хеша сохраняет контекст. Если Windows предоставляет unwind-метаданные, сохраняет функцию в пределах до 16 КиБ и записывает диапазон в лог. Сканер проверяет границы образа, читаемость страниц и непрерывность чтения. Пропущенные байты учитываются отдельно. Совпадение хеша само по себе остаётся кандидатом.

Дополнительно сохраняются 11 небольших окон конкретных незакрытых callees из HQ/interaction/getter цепочек. Вызовов этих игровых функций в probe нет. Снимки тысяч объектов Bootstrap16/17 в этом режиме не повторяются.

## Установка и получение результата

1. Получить `dinput8.dll` из артефакта Actions этой ветки. Сохранить уже установленную диагностическую DLL отдельно, если она есть. Устанавливать probe можно только в окружении, где этот способ загрузки разрешён действующими средствами защиты. Если загрузка блокируется, сохранить сообщение об ошибке.
2. Поместить DLL рядом с `TheCrew2.exe`. Запустить игру обычным способом. Probe рассчитан на x64 PE с timestamp `68D1CFB8` и SizeOfImage `05F94000`. Несовпадение фиксируется в логе и останавливает сбор.
3. Находясь в Freedrive за рулём, нажать Ctrl+Shift+F10 один раз. Дождаться строки `FACTORY_SEQUENCE_COMPLETE` в `TC2_Walkmod.log`.
4. Передать новый каталог `TC2_runtime_capture/capture_*` и `TC2_Walkmod.log`. Для отмены установки после закрытия игры восстановить прежнюю DLL либо убрать установленный probe.

Python-инструмент `tools/analyze_native_capture.py` разбирает кодовые окна одного захвата и разрешает прямые переходы в уже сохранённые диапазоны. Зависимость указана в `tools/requirements.txt`. Пример запуска после установки зависимости:

```powershell
python tools/analyze_native_capture.py 'путь_к_одному_capture' native_calls.json
```

## Пока не проверено

Результат компиляции фиксируется соответствующим запуском Actions. Запуск DLL и игровое поведение этой версии требуют игры на стороне владельца. В текущей рабочей среде игра отсутствует. Создание аватара, управление, сохранение машины и возврат в неё этой версией не реализованы. Следующая реализация зависит от анализа сохранённых factory references и подтверждения ABI.
