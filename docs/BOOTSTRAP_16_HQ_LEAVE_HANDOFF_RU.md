# Bootstrap16 — адресный анализ перехода HQ → после Leave

## Статус

Bootstrap16 — read-only диагностическая DLL. Это не мод ходьбы и не реализация выхода из транспорта.

- Нет хуков.
- Нет патчей кода.
- Нет записи в память игры.
- DLL не вызывает игровые функции и не вызывает Leave.
- Native Leave нажимается пользователем обычным способом.
- BattlEye не отключать и не обходить.

## Что изменилось после анализа Bootstrap15

### Host +0x6D0

Первый указатель вложенного объекта ведёт к структуре, в которой присутствуют смешанные указатели на код и встроенные строки. Поэтому её нельзя без проверки называть обычной C++ vtable и интерпретировать все 32 qword как виртуальные слоты.

В HQ в этой структуре найдены строки:

- \`CGameStateHQFirstPerson\`
- \`CGameTransitionHQLoadIntroMovie\`

В Freedrive вместо них присутствуют имена свойств:

- \`EpochSeconds\`
- \`IfHasStartDate\`
- \`TimespanStart\`
- \`IfHasStopDate\`
- \`TimespanStop\`

Это указывает на state-/transition-контекст Host +0x6D0, но точный тип Freedrive-объекта ещё не установлен.

### HQ state callbacks

В захваченных функциях есть несколько конкретных связей:

- RVA \`0xE8E3A0\`: записывает callback \`0xE63E40\` в объект состояния и регистрирует его через Host +0x6D0; использует компоненты, выбранные селекторами \`0x04\` и \`0x0B\`.
- RVA \`0xE92820\`: использует компоненты по селекторам \`0x20\`, \`0x23\`, \`0x30\`, а также объект Host +0x1ED0.
- RVA \`0xEC82B0\`: читает из объекта Host +0x2480 значения по смещениям \`+0x500\`, \`+0x504\`, \`+0x508\`, \`+0x3AC\` и передаёт их дальше через вложенный объект состояния.

Указатель Host +0x2480 одинаков в Freedrive и HQ, но сам объект по этому адресу в Bootstrap15 не сохранялся. Это один из главных адресных захватов Bootstrap16.

### Координатные данные и CPhotoQuestFSM

Указатель Host +0x6D8 ведёт к структуре с именем \`CPhotoQuestFSM\`. В её вложенном объекте поля \`+0x150\` и \`+0x170\` содержат координатные тройки, совпадающие с данными в компонентах по селекторам \`0x03\` и \`0x11\`.

Это подтверждает общность координатных данных, но **не доказывает**, что объект CPhotoQuestFSM является трансформом персонажа. Он может получать позицию для задач PhotoQuest.

### Недостающие байты selector

Bootstrap15 сохранял только \`0x40\` байт селектора. Однако захваченный Freedrive-код читает смещения \`0x41\` и \`0x44\`. Bootstrap16 сохраняет \`0x80\` байт и соответствующие выбранные компоненты.

## Сценарии Bootstrap16

Сбор выполняется в одном процессе и одной папке \`TC2_runtime_capture/capture_*\`.

1. **Ctrl+Shift+F10** — Freedrive с транспортом.
2. **Ctrl+Shift+F11** — HQ, персонаж пешком, непосредственно до Leave.
3. После F11 пользователь вручную выполняет штатное действие Leave в HQ и ждёт завершения перехода.
4. **Ctrl+Shift+F12** — снимок состояния после Leave.

F12 нужно нажимать после того, как игра закончила переход и находится в устойчивом состоянии. Если Leave вернул игрока к автомобилю или в меню, этот результат тоже полезен: снимок всё равно нужен.

Bootstrap16 не пытается покинуть транспорт в Freedrive и не создаёт персонажа.

## Что сохраняется

### Host и связанные объекты

- Host root до \`0x4000\`.
- Wrapper/nested objects для Host \`+0x650\`, \`+0x658\`, \`+0x6D0\`, \`+0x6D8\`.
- Первые pointer-target структуры сохраняются как raw descriptor/data; они не объявляются vtable без проверки.
- Для Host \`+0x6D0\` дополнительно сохраняются выбранные вложенные ссылки.
- Целевые объекты Host \`+0x2480\`, \`+0x1ED0\`, \`+0x1EF8\` до \`0x800\` байт, а также обнаруженные в них code-pointer fields.
- Host state references \`+0x538\`, \`+0x548\`, \`+0x5B8\`, \`+0x5C8\`.
- Host tail fields \`+0x2BC8\`, \`+0x2C08\`, \`+0x2D08\`.

### Component table и selector

- Стабильные двойные снимки component table и \`0x80\` байт selector.
- Сопоставление выбранных компонентов по логическим selector offsets, а не по изменяющимся индексам таблицы:
  \`03, 11, 06, 1C, 23, 25, 1A, 1D, 22, 20, 08, 04, 0B, 30, 41, 44\`.
- Селекторы \`0x03\`, \`0x11\`, \`0x30\` получают расширенный захват до \`0x1800\`.
- Селекторы \`0x06\`, \`0x1C\`, \`0x23\`, \`0x04\`, \`0x0B\`, \`0x20\`, \`0x41\`, \`0x44\` — до \`0x800\`.
- Остальные выбранные компоненты — до \`0x400\`.
- Для выбранных объектов сохраняются code-pointer fields и первые pointer-target структуры без предположения, что каждая из них является vtable.

### Нативный код

Сохраняются расширенные окна функций state enter/exit/update, их известных прямых callees и Freedrive-side callbacks. Все RVA проверяются относительно PE fingerprint и executable section.

## Как передать результат

После строки \`BOOTSTRAP16_SEQUENCE_COMPLETE\` передать:

- весь каталог \`TC2_runtime_capture/capture_*\`;
- \`TC2_Walkmod.log\`.

Не присылать только отдельные .bin: важны таблицы, логи, порядок сценариев и все три снимка.

## На какие вопросы должен ответить результат

1. Совпадают ли координаты Host +0x2480 с уже найденными позиционными тройками?
2. Какие поля Host +0x2480 меняются при переходе HQ → после Leave?
3. Как меняются Host +0x6D0, его вложенные объекты и связанные компоненты?
4. Какие selector offsets меняют выбранные объекты при Leave?
5. Есть ли в переходе отдельный объект персонажа, camera target или локального игрока?
6. Можно ли связать штатную HQ-передачу управления с компонентами, которые потенциально можно использовать в Freedrive?

Bootstrap16 не считается доказательством возможности свободной ходьбы. Его задача — получить конкретную цепочку штатного перехода, чтобы дальше искать способ повторить её рядом с оставленным автомобилем.
