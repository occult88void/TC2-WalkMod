# Bootstrap13: нативный жизненный цикл и указатели Host

## Цель

Bootstrap13 продолжает анализ не через полную таблицу компонентов, а через две конкретные зацепки:

1. Нативная функция по RVA `0x204800` вызывает две процедуры по RVA `0x1FA530` и `0x1FA430` в разных ветках.
2. В прежних двухсостояниях runtime-снимках значения Host `+0x650` и `+0x6D0` менялись между Freedrive и HQ; соседние поля `+0x658` и `+0x6D8` выглядели стабильными. Значения `+0x680` и `+0x700` также менялись.

Названия функций в логах Bootstrap13 являются нейтральными метками захвата, а не восстановленными символами.

## Сценарии

1. `01_FREEDRIVE_VEHICLE`: Freedrive, игрок находится в автомобиле. Нажать `Ctrl+Shift+F10`.
2. `02_HQ_PEDESTRIAN`: HQ, игрок уже управляет пешим аватаром. Нажать `Ctrl+Shift+F11`.

Leave не используется. Открытый мир не тестируется. Третьего сценария нет.

## Что собирается

### Нативный код

В первом снимке захватываются:

- `0x1FA430` — начало первой процедуры;
- `0x1FA530` — начало второй процедуры, расширенное окно до `0x420`;
- `0x204800` — расширенное окно обновляющей функции до `0xC00`;
- `0x841100` и `0x841780` — две процедуры очистки/вспомогательные кандидаты;
- прямые call-target RVA из дизассемблированного окна `0x204800` и второй процедуры: `0x796CC0`, `0x796C70`, `0x76DED0`, `0x8D9CE0`, `0x8E4D60`, `0x8DA550`, `0xA10980`, `0xA11300`, `0xA10470`, `0x1F9250`, `0x11DDA0`.

### Component Host

Для каждого состояния читается глобальный Host через RVA `0x0343C630`. Захватываются:

- корневой диапазон Host до `0x740`;
- указатели по `+0x650`, `+0x658`, `+0x6D0`, `+0x6D8`;
- до `0x200` байт по каждому валидному внешнему указателю;
- первый qword каждого объекта как кандидат на vtable;
- первые 16 qword кандидата на vtable и адреса тех элементов, которые указывают на исполняемую память;
- скалярные значения по `+0x680` и `+0x700`.

Смысл этих полей не предполагается заранее. Захват нужен, чтобы определить типы и связи по содержимому и функциям.

## Ограничения

- Только чтение памяти процесса и запись файлов захвата.
- Нет хуков, патчей кода и записи в память игры.
- Проверяется fingerprint EXE: размер образа `0x05F94000`, timestamp `0x68D1CFB8`.
- Не отключать и не обходить BattlEye.
- Не трактовать имена capture-меток как доказанные имена функций.
- Не использовать этот тест для проверки Leave или выхода в открытый мир.

## Что передать после запуска

Передать весь каталог `TC2_runtime_capture/capture_...` и `TC2_Walkmod.log`. По нему нужно:

1. Дизассемблировать полный участок обновляющей функции и обе ветви перехода.
2. Сопоставить прямые вызовы с полями Host.
3. Сравнить объекты по `+0x650` и `+0x6D0` между Freedrive и HQ.
4. Установить, какие указатели/состояния относятся к текущему игроку, аватару или транспорту, не делая выводов по одному совпадению.
