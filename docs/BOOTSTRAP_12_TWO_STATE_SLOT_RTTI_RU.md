# Bootstrap12: два сценария, слоты 0x1A и 0x1C

## Назначение

Bootstrap12 — узкий read-only сбор для сравнения двух состояний игры:

1. `01_FREEDRIVE_VEHICLE`: обычный Freedrive, игрок находится в транспорте.
2. `02_HQ_PEDESTRIAN`: HQ, игрок управляет пешим аватаром.

**Leave не используется.** Сценария выхода в открытый мир в этой диагностике нет. Не нажимать Leave для запуска второго захвата.

## Запуск

1. Собрать DLL через GitHub Actions на ветке `analysis-14-bootstrap12-two-state`.
2. Установить полученную `dinput8.dll` тем же способом, которым запускались предыдущие диагностические сборки.
3. Запустить игру и дождаться полной загрузки Freedrive с активным транспортом.
4. Нажать `Ctrl+Shift+F10`. Это первый снимок.
5. Перейти штатным способом в HQ и дождаться управления пешим аватаром.
6. Нажать `Ctrl+Shift+F11`. Это второй и последний снимок.
7. Передать каталог `TC2_runtime_capture/capture_...` и файл `TC2_Walkmod.log`.

Не запускать F11 до фактического управления пешим персонажем. В этот тест не включать Leave, открытый мир или дополнительные состояния.

## Что собирается

Для каждого из двух состояний:

- указатель Component Host и корневое окно Host;
- количество элементов и таблица компонентов;
- две последовательные копии таблицы для проверки стабильности;
- только элементы таблицы с индексами `0x1A` и `0x1C`;
- объект компонента (до `0x100` байт);
- указатели из полей объекта `+0x10` и `+0x18`, без предположения, что какое-либо из них является owner;
- первые 16 указателей vtable;
- указатель Complete Object Locator перед vtable и сырые поля RTTI;
- TypeDescriptor и ClassHierarchyDescriptor, если RTTI использует проверяемые image-relative RVA;
- небольшие окна кода для исполняемых виртуальных функций, с дедупликацией адресов между двумя снимками.

## Защита от прежней ошибки с таблицей

Таблица читается целиком в локальный буфер. Затем сразу читается верификационная копия. При несовпадении выполняется до трёх попыток. Если таблица не стабилизировалась, соответствующий снимок явно прерывается. После принятия снимка индексы `0x1A` и `0x1C` берутся **только из локальной копии**. Повторного чтения живых элементов по одному индексу нет.

Порядок компонентов может отличаться между Freedrive и HQ. Индекс рассматривается как проверяемый слот внутри каждого конкретного снимка, а не как доказательство идентичности класса.

## Ограничения и безопасность

- Только чтение памяти процесса и запись файлов захвата на диск.
- Нет хуков, патчей кода, записи в память игры или изменения игровых объектов.
- Сбор привязан к проверке размера и timestamp исполняемого файла.
- RTTI интерпретируется как MSVC x64 Complete Object Locator только после проверки сигнатуры и self-RVA. Сырые байты сохраняются независимо от успешной интерпретации.
- Наличие разных vtable или RTTI ещё не доказывает, что слот отвечает за камеру или управление. Это кандидат для последующей статической проверки.
